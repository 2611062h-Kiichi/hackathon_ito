# わからないを理解に変える支援アプリ
## 要件定義書・仕様書（MVP版）

---

# 1. プロジェクト概要

## 1.1 システム名

**わからないを理解に変える支援アプリ**

## 1.2 背景

現在の生成AIは、ユーザーから質問を受けて回答を返すことは得意である。

しかし、なぜその人が理解できないのか、どのような原因でつまずいているのかまでは分析しない。

本システムでは「分からない原因」を分析し、その原因に応じて最適な説明方法でユーザーを理解へ導くことを目的とする。

---

# 2. システムの目的

ユーザーが抱える「わからない」を、

- 原因分析
- 分類
- 解説
- 理解確認

という流れで解決し、最終的に「理解できた状態」へ到達することを目的とする。

---

# 3. システム概要

```text
わからない内容入力
        ↓
8問アンケート
        ↓
分類ロジック(Python)
        ↓
3パターン分類
        ↓
AI用質問土台生成
        ↓
Gemini API
        ↓
解説
        ↓
理解度確認
```

---

# 4. 分類パターン

## パターン1：判断できない状態

- 情報はあるが意思決定できない
- 選択肢が多く整理できない

AIの役割：選択肢整理、比較、優先順位付け

## パターン2：情報不足状態

- 必要な知識や情報が不足
- 用語や仕組みが分からない

AIの役割：知識補完、用語説明、具体例提示

## パターン3：心理的ブレーキ状態

- 失敗への不安
- 自信不足

AIの役割：不安の整理、小さな行動支援

# 5. アンケート機能

## 質問数

- 8問
- 4択回答

## 採点方式

|評価|点数|
|---|---|
|かなり当てはまる|3|
|少し当てはまる|2|
|あまり当てはまらない|1|
|当てはまらない|0|

---

# 6. 分類ロジック

AIは使用せず、Pythonによるルールベース判定を行う。

```python
decision_score = (q1+q2+q3)/3
knowledge_score = (q4+q5+q6)/3
psychological_score = (q7+q8)/2
```

最大スコアを分類結果とする。

> 実装メモ: 同点の場合は「情報不足 → 判断 → 心理的ブレーキ」の順で優先する（`backend/app/classifier.py` の `TIE_BREAK_ORDER`）。

---

# 7. AI利用方針

- 使用モデル：Gemini 2.5 Flash
- 分類にはAIを利用しない
- AIは解説と再説明のみ担当

---

# 8. AI質問土台生成

例：

入力

```text

```

分類結果

```text
情報不足
```

生成データ

```json
{
  "topic":"Git",
  "pattern":"knowledge",
  "goal":"知識補完",
  "level":"beginner"
}
```

# 9. 理解確認機能

|評価|意味|
|---|---|
|1|全くわからない|
|2|少しわかる|
|3|半分程度理解|
|4|ほぼ理解|
|5|説明できる|

---

# 10. AI利用制限

Gemini無料枠を考慮し、1セッション最大3回まで。

1. 通常説明
2. 具体例中心説明
3. 初心者向け説明

4回目以降は追加情報入力へ誘導する。

