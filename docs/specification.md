# ITOGUCHI（イトグチ）ことばマップ
## 仕様書

---

# 1. 概要

## 1.1 背景

知りたいことを、いきなり理解しようとしても難しい。
理解するには、自分がすでに知っていることから積み上げて近づくのがよい。
しかし、勉強をする人自身は「どこまでがわかっていて、どこからがわからないのか」を見分けにくい。

## 1.2 目的

知りたい言葉から、**教科書の目次に載っている見出し**をたどって「どこまでわかっているか」を確かめ、
わかる・わからないの境目を見えるようにする。
その境目を「次に勉強すること」として示し、知りたいことまでの勉強の順番をつくる。

## 1.3 対象ユーザー

- 勉強をする人。特に、大学の勉強やプログラミングのように、教科書・入門書・公式ドキュメントがある分野

---

# 2. 画面の流れ

```text
知りたい言葉を入力（例：継承）… はじめから ×（わからない）として扱う
        ↓
教科書の目次の見出しが、前提・中身の2つの枝で、継承の直下に広がる
  前提：クラスとインスタンス、メソッドと変数
  中身：メソッドのオーバーライド、スーパークラス
        ↓
見出しを押す →「こんなことができる？」（例：親クラスのメソッドを子クラスで上書きして定義できる）
  ○（わかる）：その枝はそこで止まる
  ×（わからない）：その見出しの前提・中身が、さらに広がる
        ↓
「次に勉強すること」が出る → 勉強したら ○ に変える → 次へ
        ↓
知りたい言葉が ○ になったらゴール
```

---

# 3. 機能

## 3.1 言葉の入力

- 50文字まで
- 入力した言葉とたどった言葉はAIに送られるため、個人情報は入れないよう案内する

## 3.2 ことばマップ

- 見出しは2つの枝に分ける
  - **前提**（紺の線）：その言葉の章より前の章の見出し
  - **中身**（緑の線）：その言葉の章の中の見出し
- 見出しはすべて、× を付けた言葉の直下に兄弟として並べる。見出しどうしを親子（鎖）にはしない
  - 目次の順番は「学ぶ順」であって、「前の見出しがわからないと次がわからない」とは限らないため
  - 例：官能基の中身の「ヒドロキシ基」と「カルボキシ基」は、どちらも官能基の直下に並ぶべきで、カルボキシ基の下にヒドロキシ基を置くのは誤り
  - 見出しの前提は、その見出しに × を付けたときに改めて広げる
- 知りたい言葉からは、前提を左、中身を右に広げる。見出しからは、外向きに前提を左寄り・中身を右寄りに広げる
- すでにある見出しは動かさず、新しい見出しは親の近くの空いている場所に置く（重ならない・線が言葉の上を通らない）
- 色：○ は緑、× は橙、まだ付けていない見出しは白の点線
- 別の枝で出てきた同じ見出しは、新しく作らずに点線でつなぎ、その枝はそこで止める（○× も引き継がれる）。つなぐと輪になる場合はつながない

## 3.3 見出しを押したとき

- 枝（前提／中身）と、「こんなことができる？」（その見出しが「わかる」とは何ができることか）
- 知りたい言葉は、その言葉そのものの一言説明
- 「○ わかる」「× わからない」（いつでも付け直せる。× で広げた見出しを ○ にしても、広がった見出しは残す）
- 「Webで調べる」：見出しに知りたい言葉が含まれていなければ「知りたい言葉 見出し とは」、含まれていれば「見出し とは」で Google を開く
- ○× を付けると、まだ付けていない次の見出しが自動で開く（操作を減らすため）

## 3.4 次に勉強すること

- × の見出しのうち、その先に学ぶ見出しが**すべて ○** のもの（土台がそろっていて、今すぐ勉強できる）
- 基本に近い（知りたい言葉から遠い）ものから並べる
- それぞれに、わかっている先の見出しを表示する（例：わかっている：クラス・インスタンス変数）
- 勉強して ○ に変えると、1つ上の見出しの土台がそろい、次が出る
- 前提・中身の見出しが出てこなかった × の見出しは、それ自体が土台なので、そのまま「次に勉強すること」になる
- 知りたい言葉が ○ になったら「わかるようになりました」と表示する

# 4. AIの使い方

## 4.1 見出しの選び方（AIへの命令）

- 役割：勉強をする人が「どこまでわかっているか」を確かめるための、学習の地図を作る先生
- その分野の定番の教科書・入門書・公式ドキュメントを思い浮かべ、**目次に実際に載っている見出しの言葉をそのまま**使う
- 説明的な言い換え（「コードの流用」など）や、自分で作った言葉は使わない
- 見出しの細かさは、その言葉より**1段細かく**する（章なら節、節なら項、項ならその中で学ぶ用語・反応・性質・公式など）。深くたどっても広がり続けるようにするため
- 前提（その言葉より前に学ぶ）と、中身（その言葉の中で学ぶ、1段細かい見出し）に分け、それぞれ学ぶ順に1〜3個
- 中身は必ず1個以上。その言葉そのものや、その言葉より広い見出しは中身に入れない
- 前提は、すでにマップにある見出しだけで済ませず、直前に必要な具体的な見出しを優先する
- その言葉を学び終えた後の章の見出しは出さない
- たどった道は分野の手がかりとして使い、見出しは**その言葉そのもの**の前提と中身にする
- その言葉自身と、たどった道にある言葉は見出しにしない。数を埋めるために足さない
- 見出しごとに「わかる＝何ができることか」を「〜できる」で30文字以内
- 見出しが載っている章も書かせる（言葉選びの手がかり。章の番号は不正確なことがあるので画面には出さない）

### 試してわかったこと

| 試した形 | 結果 |
|---|---|
| 関連する言葉 | 連想ゲームになり、わかりきった言葉が混ざる |
| 前提知識を1段ずつ（新しい言葉を必ず2個以上） | 数合わせの不自然な言葉が出る（例：行列 → グリッド上の座標） |
| 学ぶ順の段を1本の道で | 前だけだと短く、大事な直前の段が抜けることがある |
| 枝分かれをAIに任せる | 毎回2本になり、独立していない枝や言い換えの段が出る |
| **目次の見出し＋前提・中身の2枝（採用）** | 教科書の見出しの言葉が並び、学び終えた後の内容も出にくい |
| 見出しを「節〜章くらい」に固定 | 深くなると中身がその言葉自身になり、前提もマップにある兄弟だけになって広がらない（例：フェノール類 → ベンゼン・アルコール・フェノール類）。1段細かくする決まりに変更 |
| 2枝の見出しを学ぶ順の鎖でつなぐ | 同じ章の並列の見出しが親子になる（例：官能基 → カルボキシ基 → ヒドロキシ基）。兄弟で並べる形に変更 |

## 4.2 先読み

AIの応答には数秒かかるため、見出しが画面に出た時点で、その見出しの先を1回の呼び出しでまとめて作っておく。
× を押したときは、先読みした結果をすぐ表示する。

## 4.3 モデルと失敗時の扱い

- Gemini 3.5 Flash（考える量は最小）→ だめなら 3.5 Flash Lite の順に試す
- 混雑・回数切れ・提供終了・時間切れ（35秒）なら次のモデルへ
- すべて失敗したら「AIが混み合っています」と表示する（もう一度 × を押すと作り直す）
- APIキーが未設定のときは、AIを呼ばずにデモの見出しを返す

## 4.4 AIを呼ぶ回数

| 操作 | 回数 |
|---|---|
| はじめる | 2回（知りたい言葉 ＋ 出てきた見出しの先読み） |
| × で広げる | 1回（新しく出た見出しの先読み） |
| ○・Web検索 | 0回 |

# 5. API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/health` | 死活確認 |
| POST | `/api/mindmap/expand` | わからない言葉（最大8個）それぞれについて、目次の見出しを前提・中身の枝で返す（各1〜3個、学ぶ順、「〜できる」付き） |

リクエスト例：

```json
{
  "targets": [{ "word": "メソッドと変数", "path": ["継承"] }],
  "existing": ["継承", "メソッドと変数", "クラスとインスタンス"]
}
```

レスポンス例：

```json
{
  "results": [
    {
      "word": "メソッドと変数",
      "meaning": "クラスの中に書くデータと処理",
      "candidates": [
        { "word": "クラス", "kind": "before", "meaning": "クラスを定義できる" },
        { "word": "インスタンス変数", "kind": "inside", "meaning": "インスタンスごとにデータを持たせられる" }
      ]
    }
  ]
}
```

- `path`：知りたい言葉からその言葉の親までの経路（知りたい言葉なら空）
- `existing`：すでにマップにある言葉
- `candidates`：前提の見出し（学ぶ順）→ 中身の見出し（学ぶ順）

# 8. 独自性

```text
知りたい言葉
 ↓
教科書の目次の見出しを、前提・中身の枝で学ぶ順にたどる（× で広げ、○ で止める）
 ↓
わかる・わからないの境目が見える
 ↓
次に勉強することと、知りたいことまでの順番がわかる
```

AIに答えを聞くのではなく、**自分の知っていることから知りたいことへ登っていく道筋**を、教科書の目次の言葉でつくる。
